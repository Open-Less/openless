# Ask external editor adapter

Start one `TargetTracker` at desktop setup, before Ask can activate, and stop it during desktop shutdown (including restart). `capture_before_focus(pid, generation, access)` establishes the invocation scope and captures A before Ask activates. No PID means no A, but B can still be captured later. `capture_at_send(generation, access)` reads B for the winning admission, after deduplication and busy checks. A's collapsed caret and B's selection have separate leases. `deliver_scoped()` calls the one-shot Core claim on the native worker, after identity and baseline checks; the callback must be synchronous and should not perform I/O. These APIs need no `spawn_blocking` wrapper and never synthesize clipboard or keyboard actions.

- macOS requires Accessibility authorization and an AX text field/area exposing a verifiable focused window, control and single UTF-16 range. Range text is read directly; writes require a bounded document snapshot and a settable `AXSelectedText` on the same element. Some providers expose readonly selection but no writable range; others stop exposing their focused control while inactive or do not emit focus notifications. These are not write targets. macOS may deny restoration of a different application's focus.
- Windows reads UIA `TextPattern` selection without activation or Copy. While Ask is foreground, only a standard native Edit whose GUI thread still identifies the captured child can be verified; inactive virtual providers return unavailable. Writes are restricted to a verified Unicode Win32 `Edit` whose packed `EM_GETSEL` agrees with the UIA range, using `EM_REPLACESEL`. RichEdit, browser/WebView, custom/virtual TextPattern and ValuePattern-only providers have no supported range mutation here. Denied foreground activation, read-only state, or a result that cannot be written verbatim on a single line does not authorize a write.
- Both adapters reject password/secure or otherwise unverifiable targets. The selected limit is 4,000 Unicode scalars / 8,000 UTF-16 units; a write baseline is at most 20,000 UTF-16 units and remains on the native worker. With cursor-context permission, at most 300 Unicode characters on each side of the verified range enter composition context. Selection-only reads need no whole-document baseline. Focus events plus submit-time native identity checks invalidate stale B observations; an external visit that cannot be bound is not replaced with an older target. Changing foreground apps does not revoke A: writing restores A's exact captured control and collapsed UTF-16 range only if its document is unchanged. Editing B requires its selection and document to remain unchanged. A new invocation, hiding Ask, cancellation, timeout, or a failed verification prevents writing.
- Neither OS exposes an atomic compare-and-replace operation for these adapters. A provider can still mutate between the last check and dispatch. `Written` requires the exact expected document after the native call; timeout, uncertain completion, transformation or unverified post-state returns `Unknown` and is not retried. The ticket is consumed on the first delivery attempt, even if no mutation occurred. Clipboard fallback and its cancellation are Core/host policy.

For the ignored macOS native acceptance test, compile `openless-all/app/scripts/native-live-input-fixture.swift` and launch it with `--ask-selected`. Run `real_mac_editor_replaces_only_the_verified_fixture_selection` with `OPENLESS_NATIVE_FIXTURE_PID` set to that disposable editor's PID and with Accessibility access. The test refuses to write unless the fixture is still frontmost and its expected selection is verified.

For the two-window test, compile the same Swift file into a disposable build directory and set `OPENLESS_NATIVE_FIXTURE_BIN` to its absolute executable path. Run `real_mac_two_editors_keep_a_caret_and_b_selection_independent` with `--ignored --nocapture --test-threads=1`. The test checks the runner's Accessibility grant, launches the fixture itself, verifies its protocol and PID, and controls only its A/B windows through files in a temporary directory beside the executable. It checks insertion at A's saved UTF-16 caret after moving that caret, a read of B without mutation, replacement of B's second identical word, changed-document/changed-range refusal, and a declined claim. The child and control files are removed on completion or assertion failure.

This checks real native controls and the production `TargetTracker`, not the complete Ask window, model routing, or dictation workflow. It uses two windows in one fixture process; cross-application activation and platform-specific providers still need application-level acceptance. Do not run it concurrently with another agent's native UI checks.
