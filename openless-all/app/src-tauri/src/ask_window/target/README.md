# Ask external editor adapter

Start one `TargetTracker` at desktop setup, before Ask can activate, and stop it during desktop shutdown (including restart). `capture().await` is for the winning admission only, after deduplication and busy checks. Forward `CapturedTarget.selection` to Core and wrap `write_target` in the writer port if present. `deliver().await` calls the one-shot Core claim on the native worker, after identity and baseline checks; the callback must be synchronous and should not perform I/O. Neither API needs `spawn_blocking` around it. The tracker does not send clipboard, key or UI events.

- macOS requires Accessibility authorization and an AX text field/area exposing a verifiable focused window, control and single UTF-16 range. Range text is read directly; writes require a bounded document snapshot and a settable `AXSelectedText` on the same element. Some providers expose readonly selection but no writable range; others stop exposing their focused control while inactive or do not emit focus notifications. These are not write targets. macOS may deny restoration of a different application's focus.
- Windows reads UIA `TextPattern` selection without activation or Copy. Writes are restricted to a verified Unicode Win32 `Edit` control whose own packed `EM_GETSEL` range agrees with the UIA range, using `EM_REPLACESEL`. RichEdit, browser/WebView, custom/virtual TextPattern and ValuePattern-only providers do not have a supported range mutation here. An inaccessible virtual provider, denied foreground activation, read-only state, or a result that cannot be written verbatim on a single line does not authorize a write.
- Both adapters reject password/secure or otherwise unverifiable targets. The selected limit is 4,000 Unicode scalars / 8,000 UTF-16 units; a write baseline is at most 20,000 UTF-16 units and never leaves the native worker. Selection-only reads need no whole-document baseline. Focus events plus submit-time native identity checks invalidate stale observations; an external visit that cannot be bound is not replaced with an older target. Only the original app/window may be restored, never a different editor or range.
- Neither OS exposes an atomic compare-and-replace operation for these adapters. A provider can still mutate between the last check and dispatch. `Written` requires the exact expected document after the native call; timeout, uncertain completion, transformation or unverified post-state returns `Unknown` and is not retried. The ticket is consumed on the first delivery attempt, even if no mutation occurred. Clipboard fallback and its cancellation are Core/host policy.

For the ignored macOS native acceptance test, compile `openless-all/app/scripts/native-live-input-fixture.swift` and launch it with `--ask-selected`. Run `real_mac_editor_replaces_only_the_verified_fixture_selection` with `OPENLESS_NATIVE_FIXTURE_PID` set to that disposable editor's PID and with Accessibility access. The test refuses to write unless the fixture is still frontmost and its expected selection is verified.
