## 本轮客户端修复

- [#1092](https://github.com/Open-Less/openless/issues/1092)：离线 Sherpa 原生解码串行化。超时或丢弃调用者时，仍运行的工作线程继续持有模型与独占许可；等待中的调用不会启动第二个解码，取消后不再处理后续分块。
- [#1088](https://github.com/Open-Less/openless/issues/1088)：录音转追问保留已录问题和原选区，按会话 ID 完成转写，跳过听写润色与落字，再进入 QA；不产生速记草稿残留。
- [#1078](https://github.com/Open-Less/openless/issues/1078)：服务页不再轮询整个模型目录的远程信息；只查询下载详情选中的模型，按模型和镜像合并请求，隔离旧请求结果。
- [#1095](https://github.com/Open-Less/openless/issues/1095)、[#1093](https://github.com/Open-Less/openless/issues/1093)、[#934](https://github.com/Open-Less/openless/issues/934)：相应协议选择、原文快照/动效及音效恢复修复已合入。
- 修复速记与 Android 输入法合并后的返回类型和平台隔离错误、重复 `QuickNote` 枚举、繁中缺失翻译，以及严格检查发现的测试循环问题。
- Tauri/Linux 手机输入资源统一到 `assets/remote-input/`，现有测试和格式化入口随之更新；删除的旧资源与共享副本逐字一致。
- [#1089](https://github.com/Open-Less/openless/issues/1089)：README 的分发摘要补充必须先添加项目 tap，完整安装步骤原已包含该命令。

## 仍需外部证据的事项

- [#1090](https://github.com/Open-Less/openless/issues/1090) 的账号 HTTP 409 涉及服务端旧身份映射。私有后端 `auth.rs` 明确拒绝仅凭同名 login 接管 `github_id IS NULL` 的旧记录；客户端包不能修复服务器数据。此次未修改生产账号映射。
- [#1098](https://github.com/Open-Less/openless/issues/1098) 报告的是 stable 1.3.18 缺少 MLX 资源；本次两份包均须经过资源与签名检查，不代表已替换公开 stable 安装包。
- 火山配置状态当前已按 `authMode` 和渠道的 `providerType` 判断，相关回归通过；未使用 #1071/#1016 报告者账号验证。
- Windows IME/多屏、Linux X11/Wayland、Android 真机、Intel Mac、持续录音音效与各云服务真实密钥调用没有本次设备证据。旧 1.3.x 反馈和无法稳定复现的模型近似重复问题不据此标记关闭。
- macOS 安装包采用本机 ad-hoc 签名，未进行 Apple 公证。
