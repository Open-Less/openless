# 提案：按手势区分实时输入与完整输出

状态：设计提案，尚未实现实时写入或自动替换。
基线：`beta` / `6f9af895`（OpenLess 2.0.0-Beta.4）。

## 要解决的体验

短按与长按应提供两种明确体验：

| 手势 | 录音期间 | 停止录音后 |
| --- | --- | --- |
| 短按锁存 | 继续录音，目标应用不写入中间文本；再次按键停止 | 整段润色、校验后，一次性写入 |
| 长按 | 按住说话时，在目标输入框实时显示 ASR 原文 | 松手停止，润色并校验后，仅替换本次口述占用的文本范围 |

Auto 模式沿用现有 350 ms 分类阈值。短按仍是“按一下开始、再按一下结束”，不是一次按键就完成录音；Hold 模式按下录音、松手停止。Toggle/DoubleClick 保持现有录音启停语义并使用完整输出。按钮、CLI、Android 手势和远端输入必须明确各自策略，不能只根据全局默认快捷键模式推断来源。

本提案改变的是输入行为，不是强行将所有模型请求改成相同传输方式。短按可以在内部接收 SSE 并累积结果，但不把中间结果打进目标应用。长按实时阶段显示 ASR 原文，不声称这些文字已经经过 LLM 润色。

## 现有实现与差距

- `openless-all/app/crates/openless-core/src/hotkey_interpreter.rs` 已实现 Hold、Toggle、DoubleClick 和 Auto；Auto 使用原生事件时间戳识别长短按。
- `dictation_context.rs` 捕获独立的输入设置；快捷键语义与模型润色流式输入目前没有绑定。
- `api.rs` 的 `BackendEngineProgress::publish` 将 `TranscriptDelta` 累积到状态并发布事件，只有 `PolishDelta` 被送入 `ActiveTextInsertion`。因此“实时 ASR 可用”不等于“说话时就输入”。
- `asr/volcengine.rs` 已通过 `TextStreamChunk { offset: 0, text: full_text }` 发出全量快照。新识别结果可能改写已经识别的前缀，不能简单追加 delta。其他支持 partial sink 的服务也必须分别确认事件语义。
- `streaming_insert.rs` 的 `reconcile_final` 只支持补尾和完整插入。最终正文不以已输入文本开头时会返回 `CopyFallback`，不支持安全替换。
- `ports.rs` 的 `TextInsertionSession` 只有 write/copy/finish/cancel，需要增加能力明确、默认不支持的受保护文本范围替换接口。

短回复可能等待很久后在几个 SSE 事件中集中返回。仅凭设置里的流式开关不能判断视觉上是否逐字出现；也不能仅凭这种表现判断客户端强制采用了非流式协议。

## 拟议实现

### 1. 会话级输入策略

在 Core 捕获 `CompleteAfterStop`、`LiveTranscriptThenPolish` 和 Auto 尚未分类状态。保留原生时间戳、press_id 和取消代际保护：延迟的启动握手不能把 50 ms 短按误判成长按。350 ms 前不得写入中间文本；短按松手后锁存的录音也不得进入实时输入。

录音事件读取、手势分类与异步启动应解耦，避免原有串行 bridge 在等待 ASR/录音启动时延迟处理 Released。停录音、Esc、组合键取消、窗口关闭和新会话必须阻止旧会话继续写入。

### 2. ASR 能力与实时快照

显式声明服务是否提供录音期间的转写快照。实时接口保留完整快照和修订范围，按用户可感知的短间隔合并频繁更新。批量 ASR 保持停止后完整输出，并解释该服务暂不支持实时显示；不自动更换用户的服务，也不通过反复上传重叠音频伪装实时能力。

### 3. 原文写入与最终替换

首次输入时冻结目标应用、控件和插入范围。平台适配器必须证明能够查询和更新该范围，才启用实时原文；不支持的控件退回完整输出。

所有 ASR 修订和最终润色都走同一个受保护范围更新操作：

1. 确认仍是原控件，并验证当前范围内容与客户端上次确认的内容相同。
2. 确认光标/选区仍符合本次口述操作，且用户没有插入、删除、粘贴或移动光标。
3. 只修改本次口述的范围，保留前后正文；正确处理 UTF-16、emoji、换行及中文。
4. 验证平台真正接受了更新，不能把“事件已经发送”当作“文本已写入”。

无法确认所有权时立即停止自动修改，保留用户编辑，提示完整润色结果可复制。禁止按字符串长度盲目发送 Backspace，也禁止无条件覆盖控件全文。取消时加入仍在执行的原生操作，之后才释放输入源和会话资源。

macOS AX 操作需保留已有安全门禁、输入字段限制和消息超时，运行在阻塞线程；用于保护替换的文档基线只留在本地，不作为新增 LLM 上下文上传。Windows TSF/UIA、Linux 输入法及 Android 需分别实现能力握手；首个实现可限定 macOS 可验证的文本控件，其余平台明确回退。

### 4. 结构化结果校验

在首次完整插入或最终替换前，对内置结构化风格执行同一套有限校验：

- 同层级列表连续编号，识别重复编号和 `2. 2.` 双编号。
- 不把 `(a)` 子项重新当作顶层事项；每组子项独立编号。
- 保留年份、版本号、命令、路径、URL、引用、代码块及用户自定义格式。
- 最终插入内容与历史记录保持一致。

`output_cleaning.rs` 目前不检查列表编号；OpenAI 兼容流式路径直接传出文本，非流式响应解析会调用 `clean_polish_output`。需统一润色输出清洗语义，并考虑思考标签、套话、围栏横跨 token 的情况。QA 正文、翻译正文和自定义风格不能复用未经限定的编号替换规则。

报告中的 `&#x20;`、`2\.` 可能产生于模型、Markdown 序列化或目标编辑器转换。先比较 ASR 文本、模型原始正文、清洗后的正文及目标应用实际内容，确定责任层；不能全局解码实体或删除反斜线。诊断只保留用户明确授权的文本样本，不新增默认全文日志。

## 验收标准

- Auto 349 ms 短按不输入中间正文；350 ms 长按在支持实时 ASR/控件时，松手前可看到原文。
- 慢启动、排队释放、重复按键、过期 press_id 不改变手势分类。
- 短按停止后仅插入一次完整结果；长按停止后只替换口述范围，不追加重复正文。
- ASR 前缀改写、重复快照、offset 修订不产生重复或丢字。
- 中途手动编辑、移动光标、切换控件、控件销毁或权限丢失时，用户文本保持不变。
- Esc、服务错误和关闭流程阻止后续输入，最终操作与新会话互不穿插。
- 测试重复编号、子项重置、版本号、年份、围栏、多层列表、跨 token 标签和 Unicode 边界。
- 在真实可编辑控件验证原文出现、ASR 修订、松手润色、用户编辑保护和批量 ASR 回退。

## 与麦克风修复的关系

设备原生格式、启动恢复和空/全零录音拦截由独立麦克风 PR 处理，本提案不依赖修改用户的首选设备。这里同样不能把设备存在、流回调存活、非零音频、有效语音识别四件事混为一谈。
