# 「随便问」附件、上下文和工具契约

窗口、快捷键、提交时选区、意图分流和写回见 [统一入口契约](ask-unified-entry-contract.md)。本文保留附件、上下文和模型工具的共享约定。

个人助手的新执行边界见 [助手重写契约](ask-assistant-rewrite-contract.md)。旧 Chat 的单次搜索预判、`ASK_RESULT` 输出标记和二次模型核验不再是新助手的要求；工具循环由独立助手运行时负责。

## 后端端口与上下文来源

- **桌面 App 元数据 → ContextProvider**：在切到 Ask 前冻结显式唤起时的来源 `{ invocationId, capturedAt, foregroundApp?, desktopApps? }`。当前真正接收键盘输入的只有前台对象；后台用可见/最小化窗口所属 App 或已打开的用户 App 元数据表达，按平台能力区分 `unknown`。不把后台当成另一份前台焦点，不读取后台窗口内容、标题、浏览历史或所有进程；不假设能跨虚拟桌面枚举。Ask 已前台的后续轮使用该对话最近一次有效外部来源及时间，不把主窗/胶囊当成用户正在工作的 App。
- **`ContextProvider`**：按轮提供 `staticInstructions`（固定且版本化）和带 `source/asOf` 的 `facts`，缺失单独标原因。用户“今天在做什么”只来自已授权的本地信息或用户指定的公开检索，搜索不等于能看见本机活动。时间使用设备时钟；天气只查询用户明确给定或授权的地点，保留观测/预报的时间与来源；无地点、禁止搜索或离线时不猜。现有用量记录未提供可用的 Ask 实际金额，首版显示「无数据」，不拿 token 乘现价，也不访问个人账单或外部账户。App/用量范围须有 Ask 专属授权；开启联网、保存历史或操作系统授予可读权限不算授权。被撤销的隐藏事实不能作为后续请求或 Compact 的输入；这不等于抹掉用户已看到的聊天消息。
- **`SearchTool`**：输入限定为模型 `web_search` 工具调用中的短公开查询和调用 ID；一次助手请求可按需连续查询，全局搜索设置仍可关闭。默认「免费搜索」在客户端合并 FreeSerp 与 Keenable 的免 Key 结果，遵守端点限流，不通过 OpenLess 服务转发。「混合搜索」额外使用用户单独配置的 DeepSeek Search API Key，可能计费；原有 Bing 或支持 JSON 的 SearXNG 地址仍可按需选择。结果通过供应商协议的工具消息返回，不混入系统提示词。复用超时、网络保护和取消；不把整个 Prompt、历史、选区、附件、账单或 App 清单发给搜索服务。实际发出请求才进入 `searching`，实际读取才进入 `reading`，只有成功取回可用正文才标 `read`。搜索发现的来源和读取状态随活会话回放；部分读取失败不抹掉已发现来源。返回给模型的证据正文有预算，不放进公开事件或额外的持久化记录。模型读取的网页、选区、PDF 与动态事实始终是数据，不是系统指令。
- **`AttachmentReader`**：按 `{ conversationId, turnId, attachmentIds }` 一次性取得所有已就绪附件的只读引用，解析为选区原文、带真实页码（从 1 开始）的 PDF 文本或经验证的图像。选区完整保留到 4,000 个 Unicode 标量或 16 KiB；预览先显示前 280 个标量，展开看原文，超限提示、不静默截断。大图片优先在本机压缩；保留 48 MiB / 40 MP 的解码保护。PDF 本地处理最多 48 MiB / 100 页 / 512 KiB 提取文本，不上传原件。每轮最多 4 件。可恢复的操作错误复用主界面的弹窗 API。PDF 首版只本地提取有文字层的文档，解析器必须有可中止的资源限制；扫描件、加密、损坏和超限分开报错，不执行脚本、访问外链或做 OCR。图片首版验证 JPG/PNG，通过实际协议和模型能力双重校验后才能发送；能力不明也保留草稿并报告，不探测上传、不换渠道、不当空附件。首版可在内部按页读取，不把页范围放到公开 `submit`。文件使用选取时有界读取的内容，不在发送时重开源路径。结束对话清理临时资源，不自动删除用户原文件或既有 opt-in 历史行；「保存历史」沿用旧的文本记录范围，不新增长期保存附件原件、原文、缩略图或路径。
- **模型和 Compact**：复用现有 QA 生命周期的所有权检查及供应商底层传输，旧单槽/选区润色接口不直接接新窗口。每轮冻结已配置渠道、模型及能力；不假冒深度思考、视觉和工具支持，不静默切换供应商。固定指令与稳定历史放在前，动态事实和本轮材料放在后；遵守 [现有缓存策略](prompt-cache-policy.md)。**256K 指总窗最多 256,000 tokens**，取与供应商确认的模型限额较小者，再扣除输出、未计入的工具结果和安全余量。未知窗口使用明确的保守限制，不把输出 `max_tokens` 当成总窗；搜索回填后再计量。Compact 只替换模型输入中的旧完整轮次，保留 UI 全量消息和来源、新近完成轮及当前轮。摘要有对话与版本边界，必须完整、更小且在当前轮有效时才替换；过大附件不静默裁剪，压缩失败不修改旧摘要。KV 命中率按 provider 可比实测 `Σ缓存读入 tokens / Σ输入 tokens`，在同服务/渠道/模型/协议内聚合；缺字段显示未知，不写死百分比，不为预热多发请求。按实际调用归档已知用量，不把答复、压缩等多次请求算作同一次；聊天视图可把辅助请求与答复分开。
- **工具扩展**：聊天核心定义可取消、按 `{ conversationId, turnId, toolCallId }` 跟踪的类型化工具分派接口；常规任务注册 `web_search` 与 `calculator`，主模型工具判定阶段单独开放 `resolve_intent`。提示词优先核实时效性强或易变的公开事实；需要计算时先核实公开输入，再用本地 Rust 计算器。计算器只接受有界的数值表达式，返回精确整数或最简分数及最多 50 位小数，每轮最多三次，关闭联网仍可用；计算结果作为工具消息，不随搜索查询外发。不写锁屏、切用户、开 App 或切换主题的实现，不给模型通用 Shell、系统控制或调用特权。未来的系统操作需独立权限、用户确认及审计契约。

## PromptBox 内的附件呈现

新截图参考的是**附件在输入框里的呈现**，不是把录屏里的聊天布局复制过来。预览、引用标签和编辑区属于同一个 PromptBox 边框；不能把独立附件条放到整个输入框上方。

| 类型 | 框内呈现 |
| --- | --- |
| 图片 | 显示真实图片缩略图，角标如 `#1`，右上角有移除按钮；编辑区前可见对应的「图片 #1」引用标签，光标可以接着输入。图片加载失败时显示原因，不把空白方框当作成功预览。 |
| PDF | 用同一框内样式显示 PDF 图标、文件名和移除按钮，已知时可显示页数；编辑区的引用标签能识别这是哪个 PDF，不冒充图片预览。 |
| 选中文字 | 经提交时验证且本轮确实使用的原文可作为本轮私有材料；不在唤起时自动添加草稿卡片，也不把原文塞进可编辑的问题草稿。普通粘贴不变。 |

标签是附件的视觉引用，不是发给模型的字面文本；提交仍用 `attachmentIds`。卡片与标签指向同一附件，移除后两者同步消失，同时保留草稿与光标。布局可以加高框内内容，但不改变独立窗口尺寸。

同一个 PromptBox 边框内提供预览和引用，优先保留原组件自身的边框与样式。拖入图片时只接收浏览器提供的文件内容，不接受或转发本机路径；后端与原生选择器共用验证和登记逻辑。拖放只添加附件，不发送，不打开本地文件网页。纯附件用同一个发送入口；中文输入法选词回车不触发。不显示联网按钮或确认面板。模型调用工具时在答复旁显示 Websearch；完成后仍可查看来源。用户消息下不显示档位标签，开启思考后按钮始终为蓝色。
