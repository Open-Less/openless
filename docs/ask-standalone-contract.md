# 「随便问」独立窗口：分工、接口与验收

## 范围

「随便问」是 OpenLess 内的独立桌面聊天窗口，不是主界面的页面。**完整 [Rare UI PromptBox demo](https://www.rareui.com/components/promptbox) 是视觉和交互基线**：从 #1469 已引入的官方演示源码出发，保留初始居中布局、发送后下移的输入框、消息气泡与入场、答复渐显和 `AiStatus`；只用真实数据替换演示脚本，追加明确要求的能力。不要另设计聊天 UI、顶部工具栏、对话名称或自动生成标题；原版空白态引导语不是对话名称。独立 Vite / Tauri 容器默认 **800×920 逻辑像素**，四角圆角 16px，较小屏幕等比缩小；圆形 SVG 关闭按钮在 **macOS 左上角、Windows 右上角**。沿用 OpenLess 实际主题与亮暗色规则，只替换配色，不改 demo 的几何、层级和动效。不恢复旧主界面对话或选区润色预览，不把聊天上下文注入普通听写。

C1–C5 已分别核对设计。共享注册、事件桥接和最终联调由协调者统一完成。开发基线是 #1469 已提交的 `062540e8`（仍未合并），包含分工时最新 `beta` 的提交；不依赖此前中断留下的未提交试验代码。各组在独立工作树开发，不在主工作区或直接在 `beta` 开发。

## 边界与公共契约（V1 拟定）

### 本地 API：前端只说聊天语言

正式命名可在设计校对阶段微调；下列字段、归属及生命周期是共同契约。桌面 IPC 仅允许独立 Ask 窗口读写聊天、附件和状态，唤起可由宿主原生路由发出。无新 HTTP 服务。UI 不持有系统采集、搜索凭据、ASR 上游会话或任意文件路径权限。

| 操作 | 请求 / 响应 |
| --- | --- |
| `open`, `current`, `newConversation`, `endConversation` | `open` 唤回独立窗口与现有对话；首次没有当前对话时创建一个。`current` 只返回当前 `conversationId`。`newConversation` 显式创建新对话，不继承前一条的草稿、附件或上下文。关闭窗口只隐藏/断订阅；显式结束对话或退出时清理临时资源。 |
| `snapshot`, `events` | `snapshot({ conversationId })` 包含消息、当前轮次与累计答复、状态、来源和高水位 `sequence`；`events({ conversationId, afterSequence })` 返回 `{ events, latestSequence, truncated }`。序列在同一会话内连续，快照与序列在同一状态边界内产生。不使用全局事件总线的序号判断丢包。前端先监听再取快照并去重，发现缺口用回放补齐；缓存截断或回放仍有缺口时重取快照，不重跑模型。 |
| `submit` | `{ conversationId, clientRequestId, text, attachmentIds, options: { deepThinking } }` → `{ turnId }`。校验并取得该会话附件的读取引用后立即确认，不等待模型完成。相同请求 ID 与参数重返原 `turnId`，不同参数返回冲突；每个对话只接受一个生成中轮次。纯空白拒绝，允许仅附件的问题。Websearch 由模型调用，不接收联网开关或独立的查询确认参数。 |
| `cancel` | `{ conversationId, turnId }`；只取消该轮的模型、搜索与压缩任务，不取消新一轮；对已结束的同轮请求幂等。发送被拒绝时保留草稿；已接受的轮次若失败/取消，保留用户消息及已收到的部分答复并标记未完成，不进入后续模型历史。 |
| `addAttachment`, `removeAttachment`, `getAttachmentPreview` | Ask 专用原生文件选择器取消时不登记；成功返回附件元数据 `{ attachmentId, kind, displayName, preview?, pageCount?, sourceApp?, state, error? }`。快照/事件只带元数据：图片的尺寸和缩略图可用性、选区的原文片段和 `hasMore`、PDF 的文件名和已知页数。框内按 `{ conversationId, attachmentId }` 单独读取本地缩略图或完整选区，不给 WebView 任意路径或通用文件权限。状态 `processing/ready/error`；移除停止未完成的解析且阻止新读，不改已接受的轮次。注册和预览不上传，发送时才允许把选中的附件交给当前模型。 |
| `getSearchStatus`, `getSources`, `openSource` | 按 `{ conversationId, turnId }` 查状态和来源：`idle/searching/reading/done/no_results/error/cancelled`，来源含 `{ sourceId, url, title, snippet?, readStatus }`。仅返回本轮由搜索工具实际返回/成功读取的来源；正文链接不冒充检索结果。`openSource` 再给 `sourceId`，由宿主从实际记录中核验 HTTP(S) 后交给系统浏览器。 |

消息以 `messageId` 隔离；事件含 `conversationId`、`sequence`，必要时具有 `turnId`、`messageId`、`toolCallId`。至少支持消息接受、答复增量、思考/搜索/读取/压缩状态、来源、附件状态和轮次终态；同轮只有一个终态。状态对应真实执行，不根据回答文字猜测。异常返回结构化原因（未配置、无权限、不支持、超限、正在忙、取消或供应商失败），可让前端保留可重试的草稿。屏幕文本和来源 URL 按不可信内容渲染；外链仅允许验证过的 HTTP(S) 并走系统打开，不让 WebView 跳出 Ask。

### 后端端口与上下文来源

- **C3 采集 → C2 注入**：在切到 Ask 前冻结显式唤起时的来源 `{ invocationId, capturedAt, foregroundApp?, desktopApps? }`。当前真正接收键盘输入的只有前台对象；后台用可见/最小化窗口所属 App 或已打开的用户 App 元数据表达，按平台能力区分 `unknown`。不把后台当成另一份前台焦点，不读取后台窗口内容、标题、浏览历史或所有进程；不假设能跨虚拟桌面枚举。Ask 已前台的后续轮使用该对话最近一次有效外部来源及时间，不把主窗/胶囊当成用户正在工作的 App。
- **C2 `ContextProvider` → C1**：按轮提供 `staticInstructions`（固定且版本化）和带 `source/asOf` 的 `facts`，缺失单独标原因。用户“今天在做什么”只来自已授权的本地信息或用户指定的公开检索，搜索不等于能看见本机活动。时间使用设备时钟；天气只查询用户明确给定或授权的地点，保留观测/预报的时间与来源；无地点、禁止搜索或离线时不猜。现有用量记录未提供可用的 Ask 实际金额，首版显示「无数据」，不拿 token 乘现价，也不访问个人账单或外部账户。App/用量范围须有 Ask 专属授权；开启联网、保存历史或操作系统授予可读权限不算授权。被撤销的隐藏事实不能作为后续请求或 Compact 的输入；这不等于抹掉用户已看到的聊天消息。
- **C2 `SearchTool` → C1**：输入限定为模型 `web_search` 工具调用中的短公开查询和调用 ID，每轮至多一次；全局搜索设置仍可关闭。默认「免费搜索」在客户端合并 FreeSerp 与 Keenable 的免 Key 结果，遵守端点限流，不通过 OpenLess 服务转发。「混合搜索」额外使用用户单独配置的 DeepSeek Search API Key，可能计费；原有 Bing 或支持 JSON 的 SearXNG 地址仍可按需选择。结果通过供应商协议的工具消息返回，不混入普通提示词；私有附件和应用上下文不参与搜索决策。复用超时、网络保护和取消；不把整个 Prompt、历史、选区、附件、账单或 App 清单发给搜索服务。实际发出请求才进入 `searching`，实际读取才进入 `reading`，只有成功取回可用正文才标 `read`。搜索发现的来源和读取状态随活会话回放；部分读取失败不抹掉已发现来源。返回给模型的证据正文有预算，不放进公开事件或额外的持久化记录。模型读取的网页、选区、PDF 与动态事实始终是数据，不是系统指令。
- **C4 `AttachmentReader` → C1**：按 `{ conversationId, turnId, attachmentIds }` 一次性取得所有已就绪附件的只读引用，解析为选区原文、带真实页码（从 1 开始）的 PDF 文本或经验证的图像。选区完整保留到 4,000 个 Unicode 标量或 16 KiB；预览先显示前 280 个标量，展开看原文，超限提示、不静默截断。大图片优先在本机压缩；保留 48 MiB / 40 MP 的解码保护。PDF 本地处理最多 48 MiB / 100 页 / 512 KiB 提取文本，不上传原件。每轮最多 4 件。可恢复的操作错误复用主界面的弹窗 API。PDF 首版只本地提取有文字层的文档，解析器必须有可中止的资源限制；扫描件、加密、损坏和超限分开报错，不执行脚本、访问外链或做 OCR。图片首版验证 JPG/PNG，通过实际协议和模型能力双重校验后才能发送；能力不明也保留草稿并报告，不探测上传、不换渠道、不当空附件。首版可在内部按页读取，不把页范围放到公开 `submit`。文件使用选取时有界读取的内容，不在发送时重开源路径。结束对话清理临时资源，不自动删除用户原文件或既有 opt-in 历史行；「保存历史」沿用旧的文本记录范围，不新增长期保存附件原件、原文、缩略图或路径。
- **C1 模型和 Compact**：复用现有 QA 生命周期的所有权检查及供应商底层传输，旧单槽/选区润色接口不直接接新窗口。每轮冻结已配置渠道、模型及能力；不假冒深度思考、视觉和工具支持，不静默切换供应商。固定指令与稳定历史放在前，动态事实和本轮材料放在后；遵守 [现有缓存策略](prompt-cache-policy.md)。**256K 指总窗最多 256,000 tokens**，取与供应商确认的模型限额较小者，再扣除输出、未计入的工具结果和安全余量。未知窗口使用明确的保守限制，不把输出 `max_tokens` 当成总窗；搜索回填后再计量。Compact 只替换模型输入中的旧完整轮次，保留 UI 全量消息和来源、新近完成轮及当前轮。摘要有对话与版本边界，必须完整、更小且在当前轮有效时才替换；过大附件不静默裁剪，压缩失败不修改旧摘要。KV 命中率按 provider 可比实测 `Σ缓存读入 tokens / Σ输入 tokens`，在同服务/渠道/模型/协议内聚合；缺字段显示未知，不写死百分比，不为预热多发请求。按实际调用归档已知用量，不把答复、压缩等多次请求算作同一次；聊天视图可把辅助请求与答复分开。
- **C1 工具扩展**：聊天核心定义可取消、按 `{ conversationId, turnId, toolCallId }` 跟踪的类型化工具分派接口；当前只注册 `web_search` 与 `calculator`。提示词优先核实时效性强或易变的公开事实；需要计算时先核实公开输入，再用本地 Rust 计算器。计算器只接受有界的数值表达式，返回精确整数或最简分数及最多 50 位小数，每轮最多三次，关闭联网仍可用；计算结果作为工具消息，不随搜索查询外发。不写锁屏、切用户、开 App 或切换主题的实现，不给模型通用 Shell、系统控制或调用特权。未来的系统操作需独立权限、用户确认及审计契约。

### PromptBox 内的附件呈现

新截图参考的是**附件在输入框里的呈现**，不是把录屏里的聊天布局复制过来。预览、引用标签和编辑区属于同一个 PromptBox 边框；不能把独立附件条放到整个输入框上方。

| 类型 | 框内呈现 |
| --- | --- |
| 图片 | 显示真实图片缩略图，角标如 `#1`，右上角有移除按钮；编辑区前可见对应的「图片 #1」引用标签，光标可以接着输入。图片加载失败时显示原因，不把空白方框当作成功预览。 |
| PDF | 用同一框内样式显示 PDF 图标、文件名和移除按钮，已知时可显示页数；编辑区的引用标签能识别这是哪个 PDF，不冒充图片预览。 |
| 选中文字 | 使用「选中文字」附件卡，**卡片里直接显示所选原文的可读片段**，有来源 App 时可附上来源，长内容可展开查看。可移除，不只显示一个没有正文的标签，也不把原文塞进用户可编辑的问题草稿。普通粘贴的行为不变。 |

标签是附件的视觉引用，不是发给模型的字面文本；提交仍用 `attachmentIds`。卡片与标签指向同一附件，移除后两者同步消失，同时保留草稿与光标。布局可以加高框内内容，但不改变独立窗口尺寸。

同一个 PromptBox 边框内提供预览和引用，优先保留原组件自身的边框与样式。拖入图片时只接收浏览器提供的文件内容，不接受或转发本机路径；后端与原生选择器共用验证和登记逻辑。拖放只添加附件，不发送，不打开本地文件网页。纯附件用同一个发送入口；中文输入法选词回车不触发。不显示联网按钮或确认面板。模型调用工具时在答复旁显示 Websearch；完成后仍可查看来源。用户消息下不显示档位标签，开启思考后按钮始终为蓝色。

### 热键与附件端到端时序

1. **外部 App → 按录音键＋空格**：系统在切换窗口前捕获外部来源和显式选区，打开/唤回独立窗口并聚焦 PromptBox；有选区时在 PromptBox 内显示所选原文的附件卡，可展开、移除。不把选区写进草稿文本，不覆盖用户剪贴板；只有发送（按钮/回车或明确的组合键录音发送）才送给模型。无选区时照样打开，不附带剪贴板残留。
2. **Ask 在前台 → 组合键**：保持原编辑器、光标及窗口大小，开始普通胶囊录音；下一次组合键/正常完成时将这次转写当作一轮发送。录音开始时冻结本轮明确选用的附件与选项，不把无关的文字草稿或未绑定的公开查询送出。取消、空转写、失焦或忙时不另开轮；归属仍有效且因忙或请求失败而未发送的转写单独保留待重试，不覆盖草稿。
3. **Ask 在前台 → 单独录音键**：原胶囊、原录音模式；只在录音开始绑定的本窗口编辑目标插入最终转写，保留选区替换/光标规则，按回车才发。不能因等待 ASR 结果而向后来聚焦的别的应用插入。Ask 不在前台时的普通听写行为不变。
4. **ID**：`invocationId` 管窗口唤起/选区，`conversationId` 管聊天，`turnId` 管模型轮次，`recordingId` 独立管录音。ASR 供应商若要求远端 session，每次录音/流按该供应商契约开独立 ID；无该概念时不发送自造字段。允许同录音内合法重连，禁止跨录音复用供应商会话或把其 ID 当聊天 ID。取消或切窗后迟到的转写不可成为新一轮。

组合键固定为实际录音绑定加空格；「Fn＋空格」是 Fn 用户的示例，不迁移录音默认值，也不把 Windows 的其他按键叫作 Fn。监听只消费已确认为组合键的空格；不支持的冲突或绑定明确提示，保留原有显式打开 API。外部选区只在可以确认是原触发对象时读取并登记；窗口显示后通过快照/按序事件领取，不靠首次渲染前裸发事件。普通与组合录音都用既有麦克风租约、胶囊和供应商转写，不向 ASR 上传聊天内容；只在 Ask 确认前台时抢占本次录音键的路由。失焦/隐藏/切对话撤销该次交付及录音，不取消已经接受的聊天轮次。

## 验收顺序

1. **设计门禁（已完成）**：五组已回报可复用的文件、输入/输出、权限/失败边界及最小验收路径；协调者用本文件统一口径，不采纳另一套平行聊天架构。开发按上述分工进入独立工作树，未来系统操作保持只留边界。
2. **代码审查（提交前）**：优先审查跨模块的事件时序、会话隔离、异常和取消、隐私边界、可读性及代码归属。以真实交互的事件轨迹检查选区捕获/窗口抢焦点、两种语音行为、模型与搜索流、快照恢复、附件解析和超长对话；确认普通语音输入和主界面不变。最小验证优先，不能用模拟结果冒充真实 ASR、联网或 KV 命中率。
3. **提交后 CI**：只在实现齐备且审查通过后提交、推专用分支进入 CI；不更改工作流或门禁。记录提交、PR、各必须检查结果与仍需人工确认的真机问题。CI 绿后不合并、不部署、不顺手改别的功能。
