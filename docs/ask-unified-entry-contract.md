# Ask Anything unified entry: desktop contract

This contract supersedes the previous standalone behavior for windows, hotkeys, selection, submission and delivery. The existing [standalone contract](ask-standalone-contract.md) remains the reference for attachments, search, model/cache limits and context consent where compatible. Scope: macOS and Windows Ask only; no new HTTP API, no legacy popup, no changes to ordinary dictation or non-Ask editing.

## User flow

The current recording binding plus Space opens or focuses the `ask-anything` window with only the Rare UI PromptBox visible. The collapsed composer has no enclosing backdrop or close button, even if the external app has selected text. After an explicit submission is acknowledged and its authoritative route is `answer` or `selectionAnswer`, the same native window expands around the same input. The underlay starts at the measured prompt bounds and grows from the bottom on a curved transition to the original single-window 800 × 920 chat layout; reduced motion uses the final layout directly. Write, edit and clarify do not trigger expansion. Escape dismisses and cancels pending voice input without clearing the draft or cancelling an accepted turn; the expanded surface also has the platform-positioned close button. Reopening returns to the compact view, and replay cannot reopen a dismissed surface.

After a composer-focus acknowledgement for the current window/editor generation, the hotkey may launch the existing independent capsule. `autoVoiceOnOpen` defaults to true (including missing keys); it is applied only to the recording-key chord and never to a settings/menu open. Single-key dictation while the Ask composer is focused also uses the existing capsule. Both are insert-only, scoped to recording ID, conversation, editor instance/revision and focus generation; preserve unrelated draft text and current IME behavior. Repeated chords during active or starting recording are a focus-only action, never a stop or send. Losing the editor, changing conversation, cancellation, or a stale focus acknowledgement cannot send or insert late audio/transcript. No upload of Ask text or selection to ASR.

At explicit composer send, capture the latest verifiable external editor/document and selection, not an invocation-time selection. Remember external target identity at the focus boundary; if the user visits a different app/control before returning, use the newest eligible observation and do not fall back to an older control after an unreadable observation. Query the bound AX/UIA element at submit without activation or Clipboard/Copy. Keep native ownership, validation baseline, cursor/range and generation in the host. Do not report unavailable as no selection. Protected inputs and unsupported controls are unavailable; bounded capture can support read-only selection without authorizing it for writing. An unrelated selection is never appended to the draft or sent to the model. A selection may be included as an untrusted, ephemeral content item only for a resolved selected-text answer or edit. Existing App context consent and explicit attachment processing stay in effect.

| Route (wire) | Definition and destination |
| --- | --- |
| `answer` | An answer independent of external selection. Uses the existing chat, with no external selection content. |
| `selectionAnswer` | Interpret, explain, summarize or translate relevant selected text for inspection. Chat output, no write. Explicit reference with no verified selected text becomes `clarify`. |
| `write` | Produce new ready-to-use body text. Insert at a verified collapsed external caret if still unchanged; otherwise retain in the composer and copy. In particular, never replace an incidental nonempty selection. |
| `edit` | Explicitly change existing selected text, including polite interrogatives. Replace only the verified original range. No verified selection becomes `clarify`; never edits a draft inside Ask. |
| `clarify` | Ask for selection or clarify ambiguous intent in the composer. Never changes transcript visibility or sends outside Ask. |

A question mark is not a routing signal. “Make this shorter, please?” edits; “what does this mean?” answers. `translate and show me` answers; `translate and replace` edits. For “look up the exchange rate, calculate the price, then write a quote”, final deliverable is `write`. If distinct final deliverables are incompatible and user did not choose, clarify. Attachment-only requests retain the default answer behavior, subject to the chosen classifier and capability checks.

## Frozen boundaries

### Settings and admission

Machine-local, persisted typed values: `{ autoVoiceOnOpen: boolean, intentMode: "semanticHybrid" | "separateModel" | "mainModelTool" }`. A fresh store and explicit default recovery use `{true, separateModel}`. Saved mode selections remain valid. There is one mode enum, not two authoritative booleans. Both Beta off means hybrid; enabling either disables the other; turning the selected Beta off restores hybrid. Main Settings only: `ask_get_entry_settings()` and `ask_set_entry_settings({ settings })`, returning committed settings. Coordinator owns command/ACL registration and loading the same preference state for host and turn preparation. Worker D owns the store and Settings rendering, not plumbing inside existing `chat.rs`/`lib.rs`.

Keep composer `submit({ conversationId, clientRequestId, text, attachmentIds, options:{ deepThinking } }) -> { turnId }` and `cancel({conversationId,turnId})`; remove voice recording proof/auto-send from the final path. Same key and payload returns original ID before capture; same key and different payload conflicts. Reject busy subjects before reading any new target. Host-only lazy preparation runs inside the winning admission, captures the submit-time target once before model calls, and freezes mode, validated attachments and channel. Existing callers may retain a compatibility wrapper for the plain submit in non-desktop unit harnesses. Workers may choose internal Rust names consistent with wire. Coordinator owns IPC `chat.rs` / `wire.rs`, command registries and combining capture/delivery with the admission callback; no paths, raw native handles or target fingerprints cross IPC.

### Host-only capture and delivery

Worker B will supply `ask_window/target.rs` exposing a desktop-local `TargetTracker` with `new()`, owned `start()`/`stop()` lifecycle, async bounded `capture()` and delivery operations; it may choose its observer/platform submodule internals. `capture()` returns a `CapturedTarget` with `selection: ExternalSelection` (`None | Selected(String) | Unavailable`) and an optional opaque `WriteTarget`, separate from selection so readonly text is usable. Start and arm outside the low-level key callback; coordinator owns initializing it in shared desktop/host state. `WriteTarget` is immutable and safe to move into a blocking delivery job. Async delivery takes `Insert` vs `Replace`, text, and a one-shot authorization callback passed by the core (claim immediately before native write, after any reactivation/revalidation). Outcome distinguishes `Written`, `NotWritten`, `Unknown` and a declined claim; never fire Enter, refocus the then-current third-party editor, fall back to replace-all, or retry an uncertain write. Capture of protected/unknown/racy focus fails closed. If nonfocused AX/UIA read cannot demonstrably confirm the same original element, report unavailable; don't reactivate it just to sample. In normalized content, preserve original selected text/UTF-16 range semantics (not substring search) and line breaks.

Core worker A exposes host-injectable lazy admission input (`intent_mode`, selection status and optional verified selected text, plus a closure/trait object carrying any opaque host target), and a writer port taking requested insert/replace, plain generated text and a one-shot claim function. Coordinator adapts these ports to B. Clipboard and transcript/window side effects are not in B. For a write/edit with no delivery or `NotWritten`/`Unknown`, first retain the complete non-chat result in the core's per-turn projection, then attempt clipboard copy exactly once via a separate host port; copy failure leaves the result. Only one delivery claim per turn and only while active. Cancel before claim prevents write/copy; after claim report the observed outcome, no blind retry or imaginary rollback. Never save a write/edit to chat history or use it as a later editable draft. No external write or clipboard activity for chat/clarify.

### Projection/events and model

Continue one ordered sequence per conversation, replay and snapshot. Add a non-chat submission state (`currentTurnId`, `route`, existing activity/search state, `resultText`, `delivery`, `copyStatus`, structured error); preserve last retained result until next submission or explicit session end. UI can restore this on reopen without reenacting any external effect. Broadcast `submitted` (non-message admission) and `routeResolved { route }` for all accepted turns; the existing message `accepted`/answer delta events are exclusively chat routes after routing. Delivery progress/result is a per-turn upsert (`delivery` event, same data as snapshot), statuses `pending`, `written`, `retained`, `unknown`; clipboard is `notNeeded`, `pending`, `copied`, `failed`. Existing `activity`/`search`/`source`/`terminal` events stay conversation- and turn-scoped. The single Ask window shows incremental replies only for chat. Its expansion gate requires an acknowledged submission from the current visibility generation and that same turn’s authoritative chat route. The scoped desktop size command validates the route before resizing. A recovered route can expand the current submission even if live events lag, but recovery cannot expand a dismissed request. CSS/viewport details belong to worker C; coordinator owns native shared event emit/allowlist and command registration.

`semanticHybrid` uses conservative local intent cues (not web search) and calls the configured main model for a small typed decision only when uncertain. `separateModel` makes one isolated classifier request with no transcript output. `mainModelTool` requires the configured main model to call a registered local `resolve_intent` tool before any user-facing output and resumes the same logical model conversation with the validated routing result; protocol tool continuation may use subsequent requests but not a standalone classifier session. If classifier result/choice is invalid or protocol cannot support the mode, show a localized composer error; do not silently switch model strategy. Classifier inputs are user instruction and minimum selection-presence/reference signals, not raw external text, app content, attachments or history. Tool arguments are untrusted decisions, not permission to write. A hidden classification result never becomes a chat message or renderable draft. After routing, normal question/selection and write/edit generation share existing chat provider/tool limits; edit uses the actual selection as data, body-only output for writes. Preserve private-context search isolation and existing public-only search decision if required; never expose selected text/attachment/history/target to web search. `Web Search` indicator is driven by actual tool status in the active surface, not by routing or speculative planning.

## Ownership and acceptance

- A: Core standalone Ask runtime, prompt and provider adapters (not shared registration, settings, host or UI); tests for all routes/modes, tools and late/cancelled delivery.
- B: Native external focus observer, target capture/verification and actual insert/replace in `ask_window/target*` and strictly necessary native target helpers; no app/router/voice IPC or window work.
- C: Ask window frontend and native window/voice/hotkey modules. Keep `ask_window/chat.rs`, `wire.rs`, `lib.rs`/ACL to I1. Preserve typing, attachment, ordinary dictation and focus contracts.
- D: Ask entry setting store and Settings UI/localization, targeted settings tests; no Core/router or shared native registration. I1 registers both commands and shares the same store instance with capture/admission and key routing.
- I1: Cross-workstream IPC, registrations, result clipboard adapter, coordinator glue, integration/review, baseline lockfile and publication. No worker pushes or opens a PR. No archive snapshots are pushed with implementation.

Acceptance: deterministic contracts for four routes and clarification, all three modes and failure/no fallback, unrelated choice not leaking selection, real search then numeric calculation then writing without opening a chat, duplicate/cancel/late callback and clipboard failure. macOS and Windows: rebind recording key, open bottom only, switch to an external editor and change selection, return and submit the new selection, confirm capsule only fills, verify caret insertion and selection replacement, mutate target during generation and verify retained/copy only. Existing ask answer, attachments, search and ordinary dictation must remain functional. Review native runtime, prompt and IPC together, commit and wait for required CI on PR #1469; no automatic merge.
