## 内容与接受状态契约

现有 UI 内容所有者是 `src/features/cloud-sync/CloudSyncSection.tsx` 的 `ConsentForm`、`ProtocolWarning` 及 `src/i18n/*` 的 `cloudSyncE2ee.scope.*`、`consent*`、`protocol*` 文案；前缀均相对于 `openless-all/app/`。现有范围版本由 IPC `CLOUD_SYNC_E2EE_CONSENT_VERSION` 与 Core `cloud_sync_e2ee/dto.rs::CONSENT_VERSION` 固定为 `encrypted-full-snapshot-v1`。[F02]

Core 本地加密 `ClientSettings.consent_version` 是当前范围确认状态的真实所有者。`prepare_enable` 核验入参版本，连接并刷新远端元数据后保存该值；不等于立即启用、创建或上传。账号或 origin 变化会清掉范围确认。`create`、`unlock`、`set_enabled(true)` 和同步路径还会检查该状态。没有核实到独立正式协议版本、接受时间、文本摘要或服务端法律接受回执。[F02、F08]

因此，UI 可以重排并完整展示已有版本的告知，仍需用户主动确认后才准备启用。**本目录四份草案不是正式内容源，不可自动加载成已生效条款，也不可用现有范围确认推定接受了新协议。** 如另建版本化加载器，现阶段仅加载经产品负责人指定的既有正式内容，保留明确版本与来源；不得隐式引用草案、伪造服务端回执或填入生效日期。正式合同接受机制须另行批准、实现和验收。

## 客户端契约应持续保持

- 范围描述必须对上实际 `export_snapshot`、字段 registry、凭据 account 登记和原生 capture。要包含 API Key、私密历史、活动统计与设备档案；不能复用旧 `/me/sync`“API Key 不同步”的范围描述。[F01、F03]
- 不得因凭据读取失败以空值备份覆盖真实配置；只导出已登记账号，不枚举系统钥匙串。OAuth 凭据不进入文档，但认证路径会使用 GitHub token；两者在告知中都必须准确。[F03、F08]
- 密码只能按本地真实策略描述：NFC，不 trim/case-fold；新建和改密有额外弱密码检查。无服务端找回；记住密钥也不意味着无旧密码改密。[F05、F07、F10]
- 初次恢复须先验证并复查；常规同步可自动合并远端变化。完成条件须包括数据落盘、读回、运行态副作用与失败回滚，`recovery_required` 不能显示为完成。账号/origin/vault/key/本地代次/远端版本变更应使旧预览失效。[F09、F11]
- 对网络未知结果保留原操作和幂等语义；不得把超时、取消请求或收据 404 当成确定失败。关闭同步后已发出的操作仍可能提交，不能用文案承诺即时撤回。[F12]
- 关闭、锁定、退出、删除须保持不同含义；远端删除控制状态阻止旧设备自动重建，不能承诺离线设备本机资料也删除。[F13、F15]
- `backupRetentionDays` 取实际服务 capabilities，未知时显示未知，不静默填7。客户端当前仅校验最大不超过30天；7天是当前官方接口声明，不是编译期法律保证。[F14]
- 保持日志脱敏，不记录密码、派生密钥、OAuth/同步 token、API Key、原文历史、完整快照或冲突值。诊断日志中出现标识符、时间或 origin 的必要性与保留仍要单独评估。[F06、F08]
