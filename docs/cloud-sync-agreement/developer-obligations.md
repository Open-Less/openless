## 内容与接受状态契约

开发版运行时告知源为 `src/features/cloud-sync/disclosure.json`，由同步界面展示；前缀相对于 `openless-all/app/`。IPC `CLOUD_SYNC_E2EE_CONSENT_VERSION` 与 Core `cloud_sync_e2ee/dto.rs::CONSENT_VERSION` 在复核基线均为 `encrypted-full-snapshot-v2`。首次启用和更新确认前均需明确展示已登记 API 密钥的上传、加密与使用边界，文案应与本目录的候选内容保持一致。[F02、F03、F05、F16]

Core 本地加密 `ClientSettings.consent_version` 是当前范围确认状态的真实所有者。`prepare_enable` 核验入参版本，连接并刷新远端元数据后保存该值；初始化、恢复、启用和上传按各自路径继续。账号或 origin 变化会清掉范围确认。`create`、`unlock`、`set_enabled(true)` 和同步路径还会检查该状态。没有核实到独立正式协议版本、接受时间、文本摘要或服务端法律接受回执。[F02、F08]

开发版 UI 显示明确标注的事实告知和草案状态，用户主动确认后才准备启用。**本目录四份 Markdown 文档仅供审查；JSON 供开发告知文案同步。** 正式协议文本、版本、生效日期和接受机制须另行批准、实现和验收；正式接受记录只来自经批准及验证的流程。

## 客户端契约应持续保持

- 范围描述必须对上实际 `export_snapshot`、字段 registry、凭据 account 登记和原生 capture。启用前说明将上传已登记的 API 密钥（在客户端加密后作为密文上传），并显著列出私密历史、活动统计与设备档案。只针对现行 `/v1/` 合同描述。[F01、F03、F05]
- 凭据读取失败时终止导出，避免以空值覆盖真实配置；只导出已登记账号，不枚举系统钥匙串。分开说明客户端以服务凭据向配置端点认证、同步服务存储传输加密快照、GitHub 登录令牌单独用于同步认证及服务所见的协议元数据。[F03、F05、F06、F08、F16]
- 密码只能按本地真实策略描述：NFC，不 trim/case-fold；新建和改密有额外弱密码检查。无服务端找回；即使记住了设备解锁密钥，改密仍需当前密码。[F05、F07、F10]
- 加密告知要写清客户端使用 Argon2id 派生密钥、XChaCha20-Poly1305 认证加密、HTTPS 传输的次序，以及弱密码、设备失陷、软件漏洞和实际运营风险。对部署和安全运营的事实作独立验证，待取得证据后再作对应承诺。[F05、F06、F16]
- 初次恢复须先验证并复查；常规同步可自动合并远端变化。完成条件须包括数据落盘、读回、运行态副作用与失败回滚，`recovery_required` 不能显示为完成。账号/origin/vault/key/本地代次/远端版本变更应使旧预览失效。[F09、F11]
- 对网络未知结果保留原操作和幂等语义；不得把超时、取消请求或收据 404 当成确定失败。关闭同步后已发出的操作仍可能提交，不能用文案承诺即时撤回。[F12]
- 关闭、锁定、退出、删除须保持不同含义；远端删除控制状态阻止旧设备自动重建，不能承诺离线设备本机资料也删除。[F13、F15]
- `backupRetentionDays` 取实际服务 capabilities，未知时显示未知，不静默填7。客户端当前仅校验最大不超过30天；7天是当前官方接口声明，不是编译期法律保证。[F14]
- 保持日志脱敏，不记录密码、派生密钥、OAuth/同步 token、API Key、原文历史、完整快照或冲突值。诊断日志中出现标识符、时间或 origin 的必要性与保留仍要单独评估。[F06、F08]
