# 腾讯混元实时 ASR 长语音分段

## 行为

`Hy-ASR-3.0-preview` 的一条 OpenLess 录音可以跨多个独立 WebSocket 会话：

- 45 秒后优先在静音处结束一段；连续说话时每段最多 50 秒。
- 每段重新签名并生成新 `voice_id`，沿用原渠道和模型配置。
- 录音持续进行，切换和收尾期间的 PCM 进入队列，下一会话继续按顺序发送。
- 实时文字快照包含已完成段的全文和当前段的识别结果。每个会话从零开始的句子索引不会覆盖前段。
- 停止录音会排空音频队列并等待最后一段确认。恰好停在段边界时不建立空的下一会话。
- 仅收到 `final=1` 且客户端已发送结束指令后才确认该段完成。断线或后续段失败会报错，不将前段结果冒充整条录音成功。
- 取消会中止分段任务、清空待发送录音，并关闭正在连接或收尾的会话。

腾讯其他模型继续使用单会话。腾讯音频发送速率统一为最多 1:1 实时率，符合官方接口建议；历史音频重新识别因此需要接近录音时长，并额外计入每段收尾和建连时间。

## 实现

- `openless-all/app/crates/openless-core/src/asr/tencent_cloud.rs`：单会话传输、鉴权、识别结果归并、明确终止确认。
- `openless-all/app/crates/openless-core/src/asr/tencent_cloud/segmented.rs`：保留原公开 `TencentCloudStreamingASR` API，在内部串联多个单会话。

静音检测采用 PCM16 绝对峰值不超过 180 的连续低幅度帧，阈值累计 500 ms。当前帧为 200 ms，所以实际需要至少三个完整安静帧（600 ms）。这不是神经网络 VAD；持续背景噪声时会退回 50 秒硬切。45/50 秒是客户端预算，不是服务端的配置参数。

音频不做重叠，避免重复提交；文本不做跨段内容去重，保留用户正常重复的语句。缺点是持续讲话时硬切可能影响边界词语。当前不提供自动重试、磁盘断点恢复、并行预建下一会话或跨段服务端上下文。

## 测试（2026-09-26）

全部测试使用本机模拟 WebSocket 服务和合成 PCM，不加载真实密钥，不调用付费服务。

- 腾讯 ASR 初次定向回归：18 项通过，其中 73 秒音频按真实发送节奏跑完，验证 50+23 秒分段、完整字节序列、总时长和尾段文本。
- 随后增加切换失败、切换握手取消、录音仍开启时主动轮换三个用例。
- `cargo test --locked -p openless-core -- --skip seventy_three_seconds_rotates_at_fifty_and_keeps_the_tail`：核心单元测试 873 项通过、1 项既有忽略；该次跳过之前已通过的 73 秒测试。所有集成测试通过。
- `rustfmt --check`（仅改动的两个 Rust 文件）、`git diff --check` 通过。

仍需真实服务验收：使用 59/61/73 秒及数分钟录音，覆盖长句、静音、背景噪声，并听校切分边界。此次未打包或替换桌面安装程序。

## 官方依据

[腾讯实时语音识别 WebSocket API](https://cloud.tencent.com/document/api/1093/48982)：`Hy-ASR-3.0-preview` 限制 60 秒以内的语音输入；每个新连接使用新的 `voice_id`；建议按 1:1 实时率发送。
