## 设计与实现

遵循工具型软件的即时响应，不把展示性动画塞到高频键盘操作中。

| Before | After | Why |
| --- | --- | --- |
| 6.1 MB 启动视频，25 秒 watchdog，另加 1.2 秒退出 | 删除视频与播放器；代码生成的三条线标记，装饰运动 2.5 秒内结束，就绪即进入 | 动画不再延迟进入；真正的后端契约失败仍阻止业务操作 |
| 首帧等待 UI 同步／Keychain | 本地主题与字体预先应用、HTML 首帧、React 就绪后渐进加载；同步后台初始化 | 避免空白等待；提前操作的偏好仍进入原有 CAS 队列，不被旧镜像覆盖 |
| 所有主页面和设置随主壳加载 | 非首页页面与设置按需加载，设置高级页面首次访问才挂载 | 降低初始解析和未访问功能的常驻开销；已打开的实验页仍保留草稿 |
| 设置浮窗、双层边框 | 设置占用窗口本身，统一左栏与右侧内容，返回应用入口 | 减少嵌套；保留焦点恢复、弹出子层与待保存表单保护 |
| 快捷键长卡片和层层展开的录制控件 | 右侧内嵌命令搜索、分类、分配状态、独立 keycaps，直接点击录制 | 高频动作即时生效；冲突校验、取消、禁用、重置继续复用真实 IPC |
| 渠道拖动时直接交换整行 | 临时脱离文档流的列表、逐帧计算连续插槽、每行独立临界阻尼弹簧 | 半程拖动也有部分让位；拖动帧不写 React state；取消不保存 |
| 无键盘重排 | 拖动手柄可聚焦，方向键移动，结果播报 | 不依赖鼠标／触控；持久化失败恢复后端状态 |
| 开关用 `left` 移动 | `transform` 驱动滑块；组内邻近开关有最多 1.5px 的视觉反馈 | 不改变其他开关状态，键盘与减少动态效果时不传播运动 |
| 描述文本截断 | 有明确入口的高度展开、180° 箭头 | 仅内容变化和尺寸改变时测量，200ms 局部高度过渡 |
| 删除卡片只有淡出 | 向右下删除方向的短弧线、缩小／旋转／透明度变化；支持水平划走 | 240ms 的定向反馈，保留 6 秒撤销及删除失败恢复 |
| 标签仅变色 | 选中项轻微放大，实际增加布局占位，邻项弹簧让位 | 不覆盖相邻选项；用于风格切换 |
| 滚动页面整面 mask／纹理合成 | 移除整页滚动遮罩与装饰噪点；稳定滚动条槽位 | 降低合成开销，避免内容顶部淡隐和滚动条出现时宽度抖动 |
| WebGL 预览离开可视区域仍绘制 | 离屏和隐藏时停钟；尺寸只在 resize 时测量；减少动态效果使用静态帧 | 自动测试确认离屏绘制计数不增长，重新可见后恢复 |
| 字体与排版占满一屏 | 仅保留字体、界面大小、阅读宽度三行，使用 Base UI Select | 删除文字用途、平铺字体、预设、最近使用、预览及导入导出面板；只用本机字体 |
| 问号按钮和内嵌长说明 | 共用 `Hint`，文字虚线下划线，Base UI Tooltip 优先向上弹出 | Portal 不撑开设置容器；支持悬浮、键盘、触屏、Esc 与碰撞避让 |
| 实验模型默认显示多段说明 | 默认两个模型名称和开关，规格及启停影响放入名称提示 | 下载进度、错误、重试和完成后的渠道引导仍然可见 |

### 滚动策略

不接管 `wheel`，不对滚动事件做防抖，不安装第二套模拟惯性。macOS 触控板惯性由系统／浏览器处理，用户反向输入、触碰或停止时不会再被 JS 速度累加器拖走。保留原有历史／市场搜索的 300ms 防抖，以及流式内容的 rAF 合并。动画主要使用 transform/opacity；高度动画仅用于小型展开容器。真实触控板的加速度与制动感不能用合成 wheel 事件完全验证。

### 字体与数据范围

字体配置保存在设备本地 `ol.typography.v1`；不包含账号、密钥或任意 CSS，旧数据仍可读取。新的单一字体选择同时应用于界面、正文、标题和数字，代码保持原来的等宽字体设置。界面整体缩放继续使用原有 `ol-font-scale` 偏好和同步机制；Base UI Portal 抵消根节点缩放，再在弹层恢复字号，避免 90%／110% 下重复缩放坐标。新增排版资源提供中英文，其余语言的新增文案暂用英文。

风格卡片通过 `elementRef` 传递页面测量引用，内部与 `forwardRef` 合并，避免 Framer Motion 的 `PopChild` 在 React 18 中访问特殊属性 `props.ref`。保留 `popLayout`、滑动删除、退出动画和撤销，不修改依赖包、不屏蔽控制台警告。

### 启动测量的含义

`startupMetrics.ts` 记录导航相对时间：HTML 引导、前端代码、React 帧估计、后端就绪、壳与偏好就绪、同步桥。首屏与可交互不是同一个指标，不用假进度或动画时长抵扣真正工作。设置 → 关于与更新 → 启动诊断可查看当次数据。

一次本机 Chromium headless、生产资源、5 个新浏览器 context、模拟后端的结果：

| 指标 | 结果 |
| --- | --- |
| FCP | 32–92ms，中位数 32ms |
| 壳与偏好就绪的双 rAF 估计 | 254–350ms，中位数 256ms |
| 首屏资源请求数 | 每次 9 个 |
| 主壳 chunk（未压缩） | 整合基线 369.92KB → 约 50.46KB；设置与其余页面改为按需加载 |

这些是浏览器样本，不是原生进程冷启动，也不是优化前后速度对照；系统文件缓存、CPU/GPU 负载会影响结果。未声称 CPU 或 GPU 百分比下降。

## 预览与人工验收

Orca 当前工作区的内置浏览器：`http://127.0.0.1:5337/`。对应托管终端为 `OpenLess UI Preview`，支持源码修改后热更新。浏览器用模拟后端，不能据此验证真实麦克风、模型推理、系统级快捷键或系统权限。

建议实机检查：

1. 快捷键搜索、录制、Esc 取消、冲突提示、分类切换；检查浅色／深色、90%／110% 缩放。
2. AI 服务中的渠道上拖、半程停留、反向拖、边缘自动滚动、Esc 取消和方向键重排。
3. 设置中的开关反馈，确认只有当前开关改变；开启系统“减少动态效果”再试。
4. 风格卡片展开、水平划走、撤销、快速连续删除和切换页面。
5. 在真实 macOS 打包 App 中用触控板检验原生惯性与快速制动；测原生启动及真实 ASR。此次没有构建或验证新的原生 App 安装包。
