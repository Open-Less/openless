# 2.0.1 Windows 安装器 CI 隔离

Stable 标签 `v2.0.1-tauri` 固定在 `33d17a4e`，精确源码 CI `38876378343` 及 main CI `38878764285` 均七项通过。macOS 两架构、Android 四 ABI 已构建、下载并核验；不重建这些资产。

桌面 run `38878773775` 两次 Windows job（`116900142784`、`116916344722`）都已生成 NSIS 和数字 MSI 版本的安装包；NSIS 安装、COM/TSF/后端注册检查及卸载通过。两次均在随后的 `msiexec /i ... /qn /norestart` 开始约 1 秒后收到 runner shutdown signal，MSI 检查被取消，未上传 Windows 资产。重复位置排除了继续盲目重跑的价值，符合 MSI Restart Manager 关闭持有 TSF 组件的 runner 进程的现象；日志不把它记录为已通过安装验收。

Microsoft 官方定义 `/norestart` 不等于禁止 Restart Manager 关闭应用。CI 在真实安装器 smoke 之前，临时将 `HKLM\Software\Policies\Microsoft\Windows\Installer` 的 DWORD `DisableAutomaticApplicationShutdown` 设为 1，禁止 Windows Installer 与 Restart Manager 交互，并在 finally 恢复原值/移除本次新增属性。该设置仅存在于可丢弃的 Windows CI 主机，不写入 MSI/NSIS，不改变用户电脑策略，不跳过安装、卸载、DLL 路径或任何 COM/TSF 注册检查。

来源：[DisableAutomaticApplicationShutdown](https://learn.microsoft.com/en-us/windows/win32/msi/disableautomaticapplicationshutdown)、[MSIRESTARTMANAGERCONTROL](https://learn.microsoft.com/en-us/windows/win32/msi/msirestartmanagercontrol)。官方 Markdown 已从 MicrosoftDocs/win32 对应 desktop-src/Msi 文件核对。

工作流与契约经 PR/CI 后，仅使用已存在的管理员/草稿/精确 tag 源码/七项 CI 守卫的 Windows-only repair 入口，对 `v2.0.1-tauri` 构建并验证。应用源码、版本与标签不变；最终仍须 Windows smoke 成功、全部资产与签名核验后才公开 Stable。

## 隔离后的安装器返回值

PR #1213 精确 CI `38888000367` 七项通过并合入 beta。Windows-only run `38889597557` 不再关闭 runner，MSI 安装返回 **3010**。Microsoft 官方 [Windows Installer error codes](https://learn.microsoft.com/en-us/windows/win32/msi/error-codes) 定义它为安装成功、需要重启，旧 smoke 却将所有非零返回视为失败，尚未执行后续注册验证。

修正通用进程 helper 的可接受返回值参数：默认仍仅 0，只有 MSI 安装/卸载显式允许 0 与 3010；NSIS 保持 0-only，1603 等错误及会实际重启 CI 的 1641 仍拒绝。接受 3010 后仍完整执行文件、DLL 路径和所有 COM/TSF/后端注册检查，不将成功返回码本身当成安装验收。新增 Windows 上执行实际 helper 的六个 mock 返回值回归，不启动安装器或修改注册表。

为保留不可变应用源码，工作流单独 sparse checkout **`github.workflow_sha`** 固定的 smoke 工具脚本；应用 checkout 仍指向原始 release tag。复制的只有测试脚本，编译/打包 payload 不使用工具分支；正常 tag 构建和定向草稿修复采用同一工具来源规则。Windows 编译缓存允许失败时保存，避免 smoke 问题每次重编所有依赖。后续实际 smoke 成功前仍不公开 Stable。
