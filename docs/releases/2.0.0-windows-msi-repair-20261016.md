# 2.0.0 Windows MSI 日期构建号修复

正式版 `v2.0.0-tauri` 固定指向已经通过最终七项 CI 的 `b5e60db6ac010dfc5fdd8aae4db77e1e3a72ac7f`；标签不移动、不重建已成功的 macOS/Android。

首次桌面发版 run `38799781882` 的 Windows job `116645498144` 已完成 NSIS 编译/签名，但 MSI 在生成 WiX 对象前失败：

```text
optional build metadata in app version must be numeric-only and cannot be greater than 65535 for msi target
Required WiX object missing: .../release/wix/x64/main.wixobj
```

因此旧 ICE80 light.exe 修复路径不能处理本次失败，重复原 job 不会改变结果。应用版本 `2.0.0+build.20261016` 按用户要求保留；仅 MSI ProductVersion 通过官方 `bundle.windows.wix.version` 覆盖为 `2.0.0.0`。SDK schema 明确允许此字段，限制为 major/minor ≤255、patch/build ≤65535。配置 overlay 不包含顶层 version，不改变 App 显示版本、Rust crate 版本、更新清单或安装包日期文件名。

发布工作流新增 Windows-only 平台和显式 `release_tag` 草稿修复入口：只允许管理员、已存在未公开的 Stable 草稿、准确 tag checkout、相同提交七项 CI 全绿；上传前再次确认仍为 draft。工作流分支提供修复后的打包逻辑，应用源码始终来自原始不可变 tag。普通分支手动构建仍不发布，正常 tag 构建保持原有三平台行为。

对应契约执行实际 workflow 内嵌的 MSI 配置生成代码，覆盖日期/普通版本、数字边界、保持完整应用版本、updater 签名开关、草稿与管理员/CI 约束，以及所有 Bash 步骤语法。Windows 修复 run 还须实际生成、安装验证 NSIS/MSI 并签名/上传后，才允许公开正式版。
