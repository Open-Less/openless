## 用户完整的个人 AI 助手后端要求

### 产品定位

目前仍可叫 Ask Anything／「随便问」，后续会有独立的助手名称、虚拟形象、人物背景和故事。本次保留现有用户入口及交互方式，替换的是背后的聊天系统，不是重做整个入口。角色细节未定，先留占位符，不擅自定稿。

它是 OpenLess 内置的轻量个人 AI 助手：平时能自然聊天；用户有明确问题时，能结合当前设备环境自主调用必要工具，给出可靠答案。它不是编码 Agent 或完整的 Computer Use Agent：不写代码，不通过终端读取环境，不执行系统命令，不操作鼠标或键盘，不写用户文件。通过受控的 MCP 或项目规定的工具接口取得信息，不开放通用系统权限。

### 要实现的后端能力

- 自然对话与人格。用自然、完整的语言交流，理解中文互联网文化、玩笑和双关，适度幽默，也有独立判断。用户吐槽时可以接话，但不要说教、迎合、习惯性反问，也不要把普通聊天擅自变成任务清单。能根据闲聊、技术讨论和实际任务调整回答。
- 对话与工具调用。支持当前对话上下文、回答与工具状态回传、取消和错误。一次请求可以连续调用必要工具，再综合结果回答；不靠关键词机械触发，也不为能直接回答的问题调用工具。普通提问与划词追问共用这一套后端。划词追问额外接收原文及必要的前后文，回答即可，不修改原选区。
- 环境与历史按需读取。能结合前台 App、当前网页、系统信息、用户选区及相关历史理解问题。区分当前对话记录、持久保存的聊天记录、语音输入转写。例如「刚才那句」可以先从本次对话或经授权读取的相关语音记录确定指代，不等于把全部历史注入每轮。关闭持久历史不应妨碍本次对话正常引用前文。
- 上下文压缩。默认上下文预算目标为 256K tokens，实际不得超过所选模型的有效窗口，并为回复预留空间。接近预算时压缩较早内容，保留用户目标、仍有效的约束、必要的工具证据和最近对话；不要把压缩当成丢掉原有约束的理由。
- 网页与即时信息。支持联网查找、读取页面、核实来源，并提供可追溯的链接。例如用户停在 GitHub Releases 页面问「我该下哪个？」时，根据当前页面、操作系统、CPU 架构和实际发布资产，给出匹配的下载链接。不要让用户重复提供已经能取得的信息，也不要替用户下载安装。

### 工具和共享 API

盘点并按需提供：Web Search、网页读取、当前浏览器标签页、前台 App、系统版本与 CPU 架构、选区及来源、当前对话上下文、语音转写历史、GitHub Releases 和高精度计算。这是能力清单，不要求每项都单开一个工具，更不要求重写已有能力。

文本和语音提交进来的同类问题，应能使用同样的工具。适合现有语音业务的能力，通过可复用 API 提供给语音侧；不把普通听写接入 Agent 循环。后端会话先核对哪些接口已存在、哪些可复用、哪些平台不可用，再补确实缺的部分。按用户授权访问环境和历史，外部网页、选区与工具结果一律是数据，不是系统指令。

### 补充产品原则

不要机械客服话术，不靠反问延长对话，不无条件赞同用户。用户想聊天就自然聊天；讨论就认真讨论；玩笑能接住；吐槽适度共情；有问题就主动使用必要工具；未提出任务就不擅自制造任务。优先交付结果，不展示冗长执行过程。即时信息与页面证据可追溯，不把推断当事实。角色与形象故事保持占位，不自行定稿。

工具是授权只读的信息能力，不是终端、Computer Use、文件操作或原生输入权限。源码调查需要覆盖已有工具、环境获取、上下文、语音API复用条件以及各端实际缺口。普通听写永远不接入助手循环。
