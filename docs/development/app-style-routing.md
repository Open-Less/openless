# 按输入应用选择风格包

在 macOS 和 Windows 上打开「风格 → 润色模式 → 按应用选择风格」。每个分类和具体应用各可选择一个风格包，同一个包可供多个分类和应用共用。完成一次向目标应用落字的听写后，该应用会在列表中出现，可单独选择风格包。界面分别提供「按分类选择」和「指定应用」。应用行显示识别出的分类，未单独设置时显示当前继承的分类风格。图标由系统尽力提供，找不到时仍可通过应用名称配置。

## 选择规则

| 情况 | 结果 |
| --- | --- |
| 同一应用或分类改选另一个风格包 | 新选择替换该目标的原选择，其他目标的配置保持原样 |
| 多个应用或分类选同一个包 | 可以共用，每个目标独立保存自己的选择 |
| 同一应用命中自己的规则和分类规则 | 应用指定的包优先，分类用于继承或回退 |
| 应用没有规则，分类没有规则，或系统无法识别应用 | 查找下一层，最终使用当前手选风格及其现有默认回退 |
| 分配的包被停用、删除或因同步暂时缺失 | 保存原规则，显示不可用。使用下一层的可用包，相同 ID 的包恢复后自动继续应用 |
| 手动切换全局风格或调用方提供本次会话的包 | 全局手选用于回退。同一包仍可手选；显式会话参数继续走原有选择路径 |
| 听写开始后切换应用或编辑规则 | 本次目标和风格都使用开始时的快照。下一次听写使用新的目标和规则 |

原文、翻译、短文本跳过润色、用户自定义润色策略、选区润色和手动重新润色沿用各自的调用规则。

## 内置分类

| 分类 | 代表性应用 |
| --- | --- |
| 编程 | ChatGPT、Codex、Claude、Orca、Antigravity、Cursor、VS Code、OpenCode、T3 Code、Kiro、Trae、Conductor、Superset、Windsurf、Cherry Studio、Docker、Xcode、JetBrains IDE、终端 |
| 聊天 | 微信、QQ、企业微信、Slack、Discord、Teams、Telegram、WhatsApp、飞书、钉钉、Zoom |
| 邮件 | Apple Mail、Outlook、Thunderbird、Spark、Mimestream |
| 写作与笔记 | 备忘录、Obsidian、Notion、Typora、Bear、Ulysses |
| 办公 | Word、Excel、PowerPoint、Pages、Numbers、Keynote，Windows 的 WPS |
| 浏览器 | Safari、Chrome、Edge、Firefox、Brave、Arc、Vivaldi |

识别表集中在 `InputApp::category`。macOS 使用忽略大小写的 Bundle ID，Windows 使用宿主获得的可执行文件名。macOS 上安装成独立 Web App 的 Gemini、ChatGPT、Claude、Google AI Studio 根据独立的浏览器 Web App 标识和应用名称归入编程。普通浏览器标签页按浏览器处理。MacPaw 的同名 Gemini 文件清理工具使用其他标识。

分类只决定继承哪条用户配置。为编程选择「专为构建而生」后，ChatGPT、Orca、VS Code 等在第一次听写时就会使用它，无需先配置每个应用。

## 目标、上下文和请求

[Core 的识别表与规则存储](../../openless-all/app/crates/openless-core/src/app_style_routing.rs)集中管理分类和分配。macOS 匹配 Bundle ID。Windows 匹配实际获得焦点的进程，分类用已知可执行文件名并忽略大小写。单应用规则用可执行文件路径的本机指纹，避免同名程序共享规则并避免保存路径。Windows 应用迁移到不同执行路径后可能需要重新选择。浏览器标签页沿用浏览器分类；安装为独立 Web App 的 AI 客户端按上表识别。

[桌面宿主](../../openless-all/app/src-tauri/src/core_adapters.rs)在开始听写时复用原有成对捕获的落字目标和上下文读者。它由同一个目标提供应用名称、标识及可选光标上下文。风格选择只需要应用元数据，不需要读取文件、窗口标题或输入内容。原有光标上下文授权继续控制文档文本读取。

Core 在异步读取光标上下文和凭据之前取得有效风格包，并将模式、提示词和建议模型传给原有会话快照。常规 ASR 后润色和多模态路径继续消费同一快照。实际模型请求中的提示词取自本次快照的风格包。应用语气提示和多轮历史仅辅助理解输入，输出任务由所选风格决定；风格要求的固定输出可以重复。历史与活动统计使用同一次捕获的应用信息。后续窗口或配置变化不触发重选，也不修改全局手选风格。

宿主在最终写入时仍须验证落字目标。Windows 从同一快照取焦点窗口、进程与线程。macOS 恢复开始时的应用，能获得窗口编号时也核对窗口是否仍为原窗口。macOS 窗口信息不可得时，仍使用原有进程检查和剪贴板回退机制。同窗口内切换标签页等情况取决于宿主是否能辨别具体控件。Linux、Android、iOS 和 HarmonyOS 继续使用各自原有的输入方式和手选风格。

## 本机记录

Core 通过现有原子写入工具保存 `app-style-routing.json`。它只记录应用标识、显示名、使用状态和配置的风格包 ID。只有返回已插入或已发送粘贴的成功听写会记录应用，剪贴板回退、取消、失败和后台录音均不会新增记录。应用列表从功能启用后积累，独立于普通听写历史。两类数据均有各自的清理入口。清理应用记录会移除未配置的应用，仍有规则的应用将保留其名称、标识与规则。移除对应规则即可移除这些剩余记录。「按应用选择风格」打开时订阅现有历史变更事件，成功落字写入应用记录后刷新。窗口返回前台时也重新读取；弹窗正文独立滚动，标题和清理按钮保持可见。图标从系统或现有本机图标缓存读取。规则和应用记录不进入云同步或迁移包。

[宿主命令和返回字段](../../openless-all/app/contract/backend-2.0.json)给出读取、修改与清理契约。界面依据应用标识关联图标，缺失图标不影响选择。
