# 长录音保护

## 用户合同

普通听写在录音时长不超过 5 分钟时保持原流程；**严格超过 5 分钟**启用长录音保护，范围包含半小时以上录音。门槛按采集到的 16 kHz、单声道、16-bit PCM 时长计算，不能使用模型返回的截短时长来决定是否保留录音。

音频归档从会话开始写入，超过门槛改变的是保留与恢复策略，不是从第 5 分钟重新开始存文件。正常完成也保留整段长录音，历史中的播放、导出和重新转录继续使用同一会话文件，按既有历史保留规则清理。磁盘不可写或实际文件长度与采集量不符时报告失败，并保留可用原文，不能报告已有完整可恢复录音。

## 正常入口与恢复

`PipelineDictationEngine` 复用普通采集、冻结渠道/风格和按序交付。健康 ASR 不重跑；录音结束后沿所选风格进行最终文字处理。ASR 中断或长录音终稿为空时，使用从开头到结尾的存档重跑；恢复按最多 60 秒的连续 PCM 段串行执行，每段沿既有两次有界重试，失败不把前面几段冒充整段成功。火山实时端点沿既有存档重放节奏发送。长会话发不出结束帧时，不得仅凭较早收到的结果报告完整 ASR。

长录音润色按至多 4,000 个 Unicode 字符分段，优先在句子或换行处分界，所有输入字符按原顺序覆盖；不使用“输出必须与输入等长”之类误判润色/翻译的规则。每段使用同一冻结风格与渠道，请求关闭额外思考，协议中断或不完整响应有一次重试。模型完成前的流式片段只留在处理调用内；所有分段成功后一次发布最终结果。某段最终仍失败时，遵循既有失败策略保留完整 ASR 原文和整段音频，不交付前半段润色结果。

历史中“重新转录”也按上述音频分段处理，后段失败不覆盖原历史；“重新润色”对长原文复用同一完整文字处理路径，不再把超长原文作为一个会被信封长度限制裁切的请求。原文模式仍不请求 LLM。选区润色、其他风格与普通短录音的规则不随本功能改动。

最终 ASR 原文在进入长录音润色之前写回已有历史草稿；即使文字处理迟迟未完成或进程被中断，也不必只靠界面内存找回原文。尚未完成的草稿不标记为已插入或已润色。

Tauri 录音归档线程保持异步文件写入，待写队列限制为 32 MiB。超过容量或发生写盘、头部更新、同步失败时锁存首个错误并反馈录音会话，后续不能宣称归档完整；普通短暂积压不丢帧。最终停止要等待队列写完与 WAV 头结算。录音开始前的预录、取消、真实设备故障仍沿现有会话与资源管理，不把麦克风实际没有采集到的声音当成可恢复内容。

原始音频调试模式的临时采集前缀只写一次，后续原始 PCM 由原始通道写入；热麦克风路径不再把同一帧的处理前/后版本都追加到一个 WAV。普通播放与重放的主档案仍使用原来的格式和目录。长录音完成后通过归档头、文件长度和采集量核对完整性；Tauri 无需为这一步把半小时音频全部读入内存。

## 验证与边界

本分支的最小验证入口：

```bash
cargo test --locked -p openless-core --lib long_recording
cargo test --locked -p openless-core --lib auxiliary::tests
cargo test --locked --manifest-path src-tauri/Cargo.toml --lib wav_archive_keeps_every_frame_when_disk_worker_is_delayed
```

检查由 GitHub Actions 执行，不在用户电脑编译或录音。用例使用真实 Pipeline、31 分钟以上的合成全量 PCM、可控识别器及真实 HTTP/SSE 模型适配器，检查 5 分钟边界、首中尾音频重放、健康 ASR 不重复、尾部文本进入请求、不完整响应重试、失败片段零派发、完整原文回退，以及归档线程延迟下的全量写入。合成音频不是物理麦克风长时间采集证明，HTTP 回包也是夹具而非真实模型效果。

这些检查只能证明已发送全部输入分段、请求协议正常完成和交付顺序；不能用来保证任何模型绝不遗漏语义，也不能替代真实服务时限、网络和物理麦克风的长时间验收。当前实现针对共享传统 ASR→LLM 听写链路，不把独立 Omni 音频模型管线或云笔记的专用存储策略冒称已经验收。

稳定模式有可用的处理后音频归档时，内存 PCM 超过 8 MiB 后改用归档作为重放源；仅保留原始调试音频时继续使用内存缓冲及原有容量停止保护，不能替换增强后的 ASR 输入；停录并结算后核对完整长度，分块读取。讯飞、火山、百炼及 Qwen／StepFun 实时发送线程按各自节奏发送音频，结束帧走同一 FIFO；写入失败不得被队列排空掩盖。字节写入统计只能证明本机 WebSocket 写入，不能证明服务端逐字识别完整。

恢复、本地兜底和历史重转录按段读取，桌面适配层使用范围 I/O，避免每段再次加载整段 WAV。历史入口解析 RIFF chunk，允许合法元数据块，拒绝截短文件。活动归档持有保留策略租约，创建、处理、迁移及重转录期间排除清理。其他平台仍可能使用 RecordingArchive 的整段读取默认实现，不能据桌面验证推断已消除所有平台的内存峰值。

最低有效录音为 100 ms 非零 PCM；这只排除采集尚未就绪时的极短片段，不是音量阈值。历史草稿的长录音判断沿采集 PCM 时长更新，保持与引擎的五分钟门槛一致。

火山 45000081／45000000、设备冷启动延迟、Windows 嗡鸣仍缺少确认根因所需的真实会话证据。分段识别的语句边界质量、润色上下文和断点续跑、Omni、iOS 容量保护与 Linux 写盘解耦仍不属于已完成验收。
